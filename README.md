# Детекция ботов по потоку событий

Задача: для каждой `cookie_id` из `data/test.csv` предсказать `score` ∈ [0, 1] - оценку принадлежности к трафику сервисов автоматизированного сбора данных (`target = 1`). Метрика - Precision при Recall ≥ 70%.

## Состав репозитория

- `solution.ipynb` - полное решение: EDA, признаки, валидация, baseline, подбор гиперпараметров, формирование сабмита;
- `submission.csv` - предсказания для `data/test.csv` (колонки `cookie_id`, `score`);
- `metric.py` - функции метрик (`precision_at_recall`, `recall_at_fpr`);
- `data/` - `train.csv`, `test.csv`, `events.csv.gz`.

## Запуск

Версия Python и библиотек зафиксирована в `pyproject.toml`.

Ноутбук нужно выполнить сверху вниз (`Run All`); в конце сохраняется `submission.csv`. Для воспроизводимости результатов используется `RANDOM_STATE = 42`.

## Подход

**Обработка событий.** События присоединяются к окнам наблюдения cookie, и в работу берутся только те, что попали в суточное окно `[window_start_ts, window_end_ts)`. Названия платформ приводятся к нижнему регистру. Cookie без событий в окне получают нулевые значения признаков.

**Признаки** (на уровне `cookie_id`):

- общая активность: число событий, число уникальных типов событий и платформ, длительность сессии, возраст cookie;
- темп действий: среднее, медиана, минимум и стандартное отклонение интервалов между событиями;
- структура действий: счетчики и доли по каждому типу события, контактные действия;
- время суток: число активных часов, разброс активности, доли ночных и утренних событий;
- поиск: число уникальных запросов, доля новых запросов, глубина просмотра страниц выдачи, интервалы между поисками;
- просмотры объявлений: число уникальных объявлений, категорий и локаций, доля доминирующей категории и локации;
- мышь: число и доля событий с координатами курсора, средние смещения по осям;
- клиент: доминирующая платформа, число уникальных user-agent, признак библиотеки или headless-браузера в user-agent (`python-requests`, `curl`, `selenium` и т.д.).

Выбор признаков основан на разведочном анализе: боты активнее, действуют быстрее, чаще смотрят объявления и поиск, реже пользуются избранным и авторизацией, реже генерируют события с координатами мыши.

**Валидация.** Тестовая выборка идет во времени после обучающей, поэтому случайный `train_test_split` не подходит. Используется expanding window по дням: валидационными фолдами служат последние 4 дня train (16-19 апреля), обучение проводится на всех предыдущих днях. Метрика - Precision при Recall ≥ 70%, дополнительно ROC-AUC и PR-AUC.

## Ограничения

- Признаки строятся только по событиям внутри суточного окна, поэтому у cookie с малым числом событий (1-2) статистики интервалов и поведения вырождены в нули.
